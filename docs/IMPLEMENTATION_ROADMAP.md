# 实施路线图

该路线图按可运行、可验收的垂直切片推进。任何阶段未通过验收，不进入下一阶段。

| 阶段 | 状态 | 目标 | 验收条件 |
| --- | --- | --- | --- |
| 1. 平台地基 | 已完成 | 控制台、领域类型、场次状态机、健康接口、命令审计模型 | 本地可运行；状态机只接受合法命令；健康接口可检查 |
| 2. 数据与权限 | 进行中 | PostgreSQL、租户、RBAC、SKU 版本、场次与预检 | 直播场次、SKU 版本审批、节目段落、素材授权、命令幂等和 OIDC 操作者同步已有 PostgreSQL Repository；待接渠道 Repository 和真实成员同步 |
| 3. 媒体运行时 | 进行中 | 预制节目、RTMP、录屏、探针、备用节目 | Gateway、GPU Compose、PostgreSQL outbox 与独立 Worker 已建立；4090 上完成 4 小时试播与故障切换 |
| 4. AI 运行时 | 待开始 | MuseTalk、CosyVoice、RAG、策略与人工接管 | 高风险测试集只会拒答/转人工；商品回答可回溯 |
| 5. 试运营 | 进行中 | 真实场次、告警、复盘、实验漏斗 | 运行时服务令牌遥测上报、告警自动开闭和阈值预检已建立；待完成连续场次对照与退款后贡献毛利报告 |
| 6. 商业化 | 进行中 | 多租户、计量、额度、渠道适配、SSO、扩容 | OIDC、渠道能力矩阵已建立；待做组织隔离实测、计量、OAuth/Webhook 和商品同步 |

## 当前阶段的交付

- `apps/console`：Next.js + TypeScript 控制台。
- `lib/domain.ts`：直播运行、命令、互动问题的领域类型。
- `lib/live-run.ts`：首个受约束的运行状态机。
- `/api/health`：不暴露密钥的服务状态接口。
- 指挥台：预览、输出质量、节目单、风险互动、人工接管和命令记录。

## 阶段 1 完成后的立即动作

1. 启动本地控制台并验证类型检查、构建、健康接口。
2. 确认界面信息架构，再制作场次、商品中心和预检页面。
3. 引入数据库迁移和认证，不用前端内存状态模拟生产命令。

## 当前可并行框架

租用 GPU 前可以持续完成：商品/场次后台、策略引擎、渠道适配、审计、RBAC、数据库 Repository、容器编排和 CI。GPU 到位后只进入阶段 3/4 的媒体与 AI Runtime 集成。
