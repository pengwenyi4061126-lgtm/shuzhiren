# Shuzhiren Studio 新手优先内容与直播工坊总框架

## 1. 产品决策

**目标：** 新手提供人物素材、商品资料和简单意图，就能完成可预览、可审核的数字人录播视频，或把同一份内容准备成可预检的直播场次。

**定位：** 将素材、商品事实、文案、数字人、录播和直播连成一条制作流程。用户不必会写提示词；系统负责引导、生成草稿、检查和预览。产品不承诺自动爆款，也不把自动生成等同于无人审核开播。

核心原则：

1. 一个内容项目有两个输出：`录播视频`、`直播场次`，也可同时生成。
2. 用户给目标、受众、风格、时长和重点，系统将其转换成脚本和场景。
3. 商品事实来自用户确认的资料或已批准商品版本；模型不得编造价格、功效、资质、库存或售后承诺。
4. 生成结果先预览、修改、审核，再导出或转成直播草稿。
5. 单张 4090 首发目标为单路、720p、半身固定镜头；直播稳定性高于离线生成速度。

## 2. 三家产品的借鉴点

| 产品 | 可借鉴的做法 | 对 Shuzhiren 的启发 |
|---|---|---|
| 腾讯云 AIGC 直播 | 在直播间管理商品和话术，可按风格生成话术并试听；配置数字人、声音、背景和推流。 | 商品、文案、试听和直播配置共用项目上下文，生成结果可编辑。 |
| 华为云 MetaStudio | 素材画布、角色/背景/贴图/商品、场景剧本、互动规则与推流配置形成制作流程。 | 用场景编排和实际画面预览，让新手看到内容如何组合。 |
| 百度数字员工 / 一镜 / 曦灵 | 数字人运营、视频、互动和直播相互关联，覆盖脚本、互动和场控。 | 同一人物、声音、商品和脚本资产复用于录播与直播。 |

这些是可组合的工作流，不代表任意照片都能一步变成高质量实时主播。产品必须明确输入类型、输出类型和能力验证状态；未验收能力须明确标注未验证。

## 3. 用户与工作区

首发服务不会写脚本的新手商家、要复用模板的内容运营、负责预检和接管的场控。

新手工作区四个入口：**工作台**（项目/待处理）、**内容工坊**（素材/脚本/场景/预览/渲染）、**直播场控**（预览/互动/告警/接管）、**效果复盘**（录播/直播结果与问题回放）。商品事实、素材授权、策略、成员、渠道、运行时和审计留在高级管理区；新手主流程按需调用，不要求用户先理解后台菜单。

## 4. 新手主流程

```text
新建项目 -> 选择录播/直播/两者 -> 上传素材和商品资料
 -> 自动检查并补资料 -> 选择/生成形象、声音和模板
 -> 生成脚本与场景 -> 预览、修改、审核
 -> 导出录播，或转直播场次草稿 -> 预检/批准/场控开播
 -> 回放和复盘
```

### 4.1 意图向导

用表单替代空白提示词：目标（卖货/上新/讲解/活动/FAQ）、商品、受众、风格、时长、语言/画幅、必须表达与禁说内容、行动引导。允许用户直接描述，由系统转换成字段并确认。系统提示词由产品维护和版本化，新手编辑的是脚本与简单选项。

### 4.2 上传与整理

接收人物照片/视频、商品图片/视频、品牌 Logo、背景、现成脚本和音频；自动检查时长、分辨率、音轨和方向，抽取 OCR/ASR 文本及关键帧，提示“可用/需裁切/缺声音/画质不足/授权待确认”。

| 人物输入 | 首发处理 | 能力标识 |
|---|---|---|
| 授权人物视频 | 异步生成可驱动 Avatar 候选，预处理并预览 | 实机验收后才标“可直播” |
| 人物照片 | 照片播报视频路线 | 首发只承诺播报视频；实时直播另行适配验收 |
| 已有数字人 | 导入、核验、审批和版本登记 | 标记录播/直播兼容性 |

商品图不能作为价格、库存、资质、优惠或售后的事实来源；这些字段须用户确认或引用已批准商品版本。

### 4.3 文案、提示词与场景

基于确认的商品事实、品牌语气、受众、时长、渠道风格和禁说规则，生成主脚本及短/标准/详细版本；拆分开场、介绍、证据卖点、互动、行动引导、结束语。商品断言附事实来源，证据不足则要求补充。生成时长估算、字幕断句、口播断句和互动回复草稿。

从“单品讲解、多品轮播、新品介绍、知识讲解”模板开始。桌面编辑器三栏：左侧段落列表、中间实际构图预览、右侧脚本/商品/声音/字幕/画面设置。支持逐段试听、预览渲染、整片预览、版本对比和错误定位；预览与正式输出使用同一版配置。

### 4.4 审核与双输出

- **录播：** 异步渲染字幕、商品画面、AI 标识和审计元数据，失败可重试，不覆盖已批准版本。
- **直播：** 映射成现有 Show/Program 草稿，绑定商品版本、互动规则、AI 身份提示、渠道和备用节目，再走现有预检与批准。

修改产生新版本。直播场控显示画面、当前段落、GPU/语音/推流状态、互动与风险，支持暂停、切备用、转人工、结束；结束后把录屏、脚本、商品事实、互动和异常挂回项目复盘。

### 4.5 “一个项目、两个输出”的状态边界

内容项目是唯一编辑源；录播与直播不是两份各自维护的项目。商品事实版本、脚本修订、已选素材和审核记录由项目持有；两个输出保存各自的生成版本，并记录创建时引用的项目修订。项目修改后，旧输出保留为历史版本并显示“来源旧版”，不得静默覆盖或继续冒充当前版本。

```text
共享内容：项目草稿 -> 商品事实确认 -> 素材确认 -> 脚本生成/编辑 -> 脚本审核
                                                    |
                      +-----------------------------+-----------------------------+
                      |                                                           |
录播输出：照片播报/视频渲染 -> 成片预览 -> 成片审核 -> 保存/下载/复盘
直播输出：人物视频 -> Avatar 构建 -> 候选预览 -> 人工审核 -> 正式发布
         -> 项目绑定运行时形象 -> Show/Program 草稿 -> 运行时预检 -> 批准/开播
```

上述两条支路必须采用不同的“完成”定义：录播以可播放且通过成片检查的版本为完成；直播以已发布的运行时兼容形象、冻结的 Show/Program 和通过预检的场次为可开播。Avatar 候选预览、人工批准和正式发布是三个不同状态；预览帧不等于 LiveTalking 可加载的 Avatar，批准也不自动改变正在运行的 RTMP 会话。项目绑定和预检必须核对当前项目修订、形象版本与 Show 修订，任一来源变化都要求重新检查。

### 4.6 首发桌面交互

1. 用户先创建/打开内容项目并选择“录播”“直播”或“两者”；后续步骤始终在当前项目上下文中完成。
2. 用户先确认商品事实、素材和脚本；一个脚本审核结果供两个输出复用，编辑后必须重新审核。
3. 输出区并列显示录播与直播的状态、版本和下一步操作。录播可保存为独立成片；直播先生成草稿场次，完成素材/形象、渠道、AI 身份提示、节目单和运行时预检后才允许批准开播。
4. 两条输出分别显示阻塞原因和续办入口；一个输出失败不丢失另一个输出，也不清除共享项目内容。

照片路线默认只承诺“照片 + 配音/字幕的录播视频”。没有通过独立运行时适配及实机验收前，照片不得显示成直播形象选项。单张 4090 首发仍维持单路实时直播，离线 Avatar 构建与录播渲染必须服从直播优先调度。

## 5. 系统总架构

```text
桌面控制台：项目向导 / 场景编辑器 / 预览 / 场控
                         |
Control Plane：项目 / 素材 / 商品事实 / 脚本 / 审批 / Show
                         |
Job Orchestrator + Queue
 |-- 素材探测、转码、ASR/OCR
 |-- Avatar Builder（独立、可写的生成容器）
 |-- Script Assistant / TTS / Preview / Offline Render
                         |
Media Runtime：LiveTalking + MuseTalk + CosyVoice + FFmpeg
 |-- 单路 RTMP/WebRTC / 画面层 / 录制 / 输出探针
                         |
直播平台或录播文件
```

服务职责：

- Control Plane 是项目、商品事实、版本、审批和 Show 状态的权威来源。
- 对象存储保存源素材、派生素材、预览、成片和录屏；用短期上传/下载地址，大文件不经过业务 API。
- Orchestrator 记录任务状态、进度、资源、重试与结果，支持取消、追踪和幂等。
- AI/Content Service 提供提示模板、脚本生成、事实绑定、ASR/OCR、字幕和质量检查，模型可替换。
- Avatar Builder 与直播容器隔离；生成结果经审核后才发布到运行时只读素材卷。
- Live Runtime 只消费已批准、冻结的 Show/Program。
- Analytics 按渠道、场次、SKU、脚本版本和互动策略记录结果来源。

## 6. 单张 4090 调度

```text
P0 实时直播和输出探针 > P1 直播所需语音/互动 > P2 Avatar 预处理/录播渲染/批处理
```

- 首发一个实时 Avatar 会话；LiveTalking Compose 固定 `--max_session 1`，部署检查会拒绝该参数缺失、重复或大于 1。直播期间暂停或限流离线生成任务；其他任务排队，不虚报完成时间。
- CosyVoice 与 MuseTalk 共卡须做并发、长时实测；不稳定时将 TTS/LLM 移到受控 API 或第二 GPU。
- Worker 监控显存、温度、利用率、队列、失败和帧率；资源不足时暂停离线任务并降级。
- 对话模型不具备推流、商品写入或开播权限。

## 7. 数据对象与状态

核心对象：`CreationProject`、`SourceAsset`、`AssetDerivative`、`PersonaVersion`、`VoiceVersion`、`ProductTruthVersion`、`ScriptVersion`、`Scene`、`GenerationJob`、`PreviewArtifact`、`RenderArtifact`、`Approval`、`PublishBundle`。版本记录源素材哈希、授权、提示模板、模型/权重、商品事实、脚本、审核人和输出哈希。

```text
DRAFT -> UPLOADING -> CHECKING -> NEEDS_INPUT -> GENERATING
 -> PREVIEW_READY -> EDITING -> REVIEW -> APPROVED
 -> EXPORT_QUEUED -> EXPORTED | SHOW_DRAFT -> PREFLIGHT -> ARMED -> LIVE -> ENDED -> REVIEWED
```

失败保留上下文并给出可读原因/重试步骤。审核失败、授权缺失、商品事实不足、GPU 不足须分别提示。

Avatar 生命周期单独记录，不与素材审核或脚本审核合并：

```text
SOURCE_APPROVED -> BUILD_QUEUED -> BUILDING -> CANDIDATE_PREVIEW_READY
 -> HUMAN_APPROVED -> PUBLISH_QUEUED -> PUBLISHED -> RUNTIME_COMPATIBLE
 -> PROJECT_BOUND -> SHOW_PREFLIGHTED -> LIVE_READY
```

`HUMAN_APPROVED` 仅表示候选得到人工审核；发布器必须校验候选清单和源校验和，在运行时只读形象卷内原子安装；LiveTalking 必须确认实际加载成功后才记为 `RUNTIME_COMPATIBLE`。任何项目修订、源素材版本或 Avatar 版本不匹配都会阻止绑定/预检。直播中的形象变更须经明确的会话边界执行，不能以改数据库字段代替运行时切换。

## 8. 分期建设与验收

### P0：单商品新手闭环

- 项目向导、素材上传；人物视频 Avatar 异步任务、状态、预览、审批和发布；照片先做照片播报视频。
- 商品资料导入/确认、事实校验、有依据的脚本草稿；模板、逐段试听、画面预览。
- 录播预览和异步导出；一键转 Show/Program 草稿，接现有身份提示、策略和预检。
- 单 Avatar 4090 实机验收和录制回放。

**体验验收：**不输入原始提示词也能完成示例项目；资料不足时由具体问题引导；一个项目内完成预览、修改、审核和双输出选择。

**内容验收：**商品断言可追溯；可逐段试听定位；修改产生新版本，不改写已批准版本。

**实机验收：**记录首帧/首音延迟、稳定帧率、峰值显存、音画偏差、掉帧、渲染耗时和恢复情况；离线任务不损害直播；成片和推流都做实际播放检查。

### P1：运营效率与平台接入

- 多 SKU 模板、品牌语气、脚本复用；互动问答和场景切换可视化。
- 照片形象用于实时直播的适配及验收。
- 抖音 OAuth、原生事件、商品同步、账单 Adapter 按独立规格完成；UI 完成不代表平台接通。
- 录播/直播结果归因到商品与脚本版本。

### P2：规模化

- 多平台能力矩阵、多 GPU、并发直播、批量项目和企业空间。
- 多渠道实验、退款后贡献毛利和成本核算。

## 11. 当前实现状态

素材续接：桌面内容工坊在当前页面弹出素材上传表单，保留项目草稿；上传后自动刷新待审队列。管理员/审核员可在同一弹窗批准素材，批准后自动加入当前项目；操作者不能批准，分析员不能上传。只有已批准素材可进入录播或直播输出，照片仍只进入录播分支。

内容工坊现在提供项目草稿、审核商品事实选择、已批准素材关联、基于审核事实生成的亲切/专业/问题优先脚本（简短/标准/详细）、共享脚本编辑、照片播报 WebM 本地生成/预览/下载、录播脚本包导出，以及创建 Show/Program 草稿并返回预检入口。输出区按当前项目汇总录播成片数量和直播场次数；本机 IndexedDB 保留可离线预览的成片副本，配置生产数据库与媒体证据服务后，审核通过的 WebM 会通过短时授权直传对象存储并登记为独立项目录播版本，不作为普通素材或直播录像。服务端版本保存商品事实/脚本摘要、项目修订、照片/声线来源、校验和、对象版本及证据引用，采用租户 RLS 和追加式不可变记录；项目服务端成片列表与按项目/版本授权的短时下载接口已进入控制台，跨设备取回仍要求部署本仓库的媒体证据服务并配置签名读取契约。录播配音可从项目已选的已批准声线调用 Runtime Gateway/CosyVoice 生成，也可上传音频或录制真人口播；语音请求要求当前脚本已审核，Gateway 对离线预览与直播开播合成使用互斥锁，并在存在活跃直播场次时拒绝离线预览。该配音仍与静态照片和字幕在浏览器合成为 WebM，不代表动态口型 Avatar。生成脚本只取已审核商品名、卖点、价格和 FAQ，不自动补商品功效、资质或承诺；生成稿可编辑，录播字幕和直播段落共用保存后的同一份脚本。浏览器成片使用项目照片的重新选择文件，并在正式素材模式下比对 SHA-256；照片、字幕和口播音轨在当前桌面浏览器合成。每次本机保存生成独立版本，项目可切换历史成片，旧版不会被新成片覆盖。每个版本记录对应的商品事实版本；切换商品事实、脚本或素材，或当前脚本审核失效后，旧预览不能保存为当前项目成片，需重新预览并审核。既有单成片本机记录会在首次打开版本库时迁移；清理浏览器数据仍会删除本机副本。项目所选素材 ID 会随直播输出创建传入控制面；控制面在租户事务中重新核验素材状态，并优先将其中可直播的人像视频、声音、讲品视频和音乐绑定到 Show 修订，照片类型不会绑定到直播人像。节目单写入或项目关联失败后，同一页面可按项目和精确请求内容续用草稿；创建请求使用租户隔离的持久化幂等键，网络响应丢失后重复提交会返回原场次，同键不同载荷会被拒绝。内容项目和素材/直播输出关联保存在租户隔离的 PostgreSQL 表中；演示模式使用进程内存储，仅用于本地试用。

录播保存会先把成片 Blob、归档请求 UUID 和待处理状态写入本机 IndexedDB，再发起对象存储上传；刷新后仍可重试。服务端按租户和归档请求 UUID 幂等登记（迁移 `102_project_recording_archive_idempotency.sql`），重复提交返回原不可变版本，同一请求 UUID 对应不同内容则拒绝，避免响应丢失造成重复成片。

内容工坊现在直接显示商品事实可用性：来源同步超过 24 小时、尚未生效、已失效或字段不完整时，页面说明具体原因，并链接到商品中心；刷新后会优先切换到该商品最新的有效已批准版本，并要求重新生成/审核脚本。事实无效期间，项目保存、脚本审核、录播制作和直播输出均不可执行，避免先让用户走完整条流程后才在服务端遇到拒绝。

新关联的直播场次会记录创建时的项目修订；项目后续保存新修订时，内容工坊会将旧场次标记为来源旧版，历史场次则显示来源版本未知。关联请求携带预期修订号并在服务端事务中核对，避免并发编辑导致错误归属；同时服务端会确认 Show 节目单的讲解段落完整匹配当前审核脚本，且关联时审核仍有效。

照片播报 WebM 在进入人工预览和项目版本保存前，会自动检查 WebM 容器类型、首帧可解码状态、720 × 1280 画幅，以及必须可读取的成片时长与口播长度；时长必须在 1 秒到 5 分钟范围内且两者差值不超过 2 秒。浏览器无法读取任一时长时会阻止进入保存步骤，不再跳过该项检查。人工仍需检查实际画面、字幕和音频。自动检查目前运行在桌面浏览器，不替代服务端异步渲染和独立质量审核。

正式服务端归档还会使用隔离的 `ffprobe` 独立确认实际对象具有 720 × 1280 视频流、至少一条音轨及 1 秒到 5 分钟时长；质检报告随不可变版本入库，历史版本明确标记未做服务端质检。人工仍需检查商品事实呈现。成片仍由桌面浏览器同步合成；服务端异步渲染与包含商品事实/OCR/语音内容核对的独立审核尚未实现。

照片形象作为独立的 `portrait_photo` 素材类型，只接受图片内容校验且不满足直播所需的 `portrait` 视频资产类型。仓库中的媒体证据服务已支持该类型及 JPEG/PNG MIME；项目已选照片用于录播分支，可直播形象仍需视频素材、运行时版本和实际验收。

肖像视频登记现先在当前桌面浏览器解码并预览源文件，读取时长、分辨率、方向及浏览器可检测到的音轨；首帧不可解码时不允许提交上传，横屏和低分辨率只触发人工复核提示。此处是上传前素材检查，不是 Avatar Builder，也不声称完成人脸适配、动态口型或可直播认证；审核及运行时验收仍是单独步骤。

以下能力仍属于首发闭环的待建项：媒体服务的对象存储直传/校验/签名读取服务实际部署、动态口型照片播报、服务端录播异步任务与独立成片质量审核、产品事实完整的成片校验，以及单张 4090 的 P0/P1/P2 资源调度和实机验收。Avatar Builder 已有租户隔离持久任务账本（迁移 `097_avatar_build_jobs.sql`）、候选预览约束（迁移 `098_avatar_build_preview.sql`）、不可变人工审核决定（迁移 `099_avatar_build_review.sql`）、审核后发布状态与队列（迁移 `100_avatar_build_publish.sql`）、项目级提交/查询/审核 API 和桌面内容工坊入口。任务记录项目修订及源素材校验和/对象版本/证据；提交服务会复核素材仍绑定当前项目、已批准且未过期，并向媒体证据服务重新核验对象，活动任务按项目与源素材防重。Runtime Worker 已能安全领取并恢复生成租约，持有与开播相同的 advisory GPU 锁，检查所有租户的活动场次后才消费构建任务；它校验源文件 SHA-256、驱动隔离 Builder，并将租户候选预览帧持久化供工坊查看。Builder 使用源校验和绑定候选清单，先在临时目录生成和校验文件，再原子提交完整候选；重复请求复用结果，Builder 重启后可验证清单并恢复已完成结果。审核批准会排入独立发布队列；CPU-only Publisher 对候选卷只读、对运行时形象卷写入，重新校验每个候选文件哈希并原子安装，失败可重试且记录审计。项目级形象选择与直播输出绑定已落库（迁移 `101_creation_project_avatar_selection.sql`）；桌面 Studio 显示已发布形象及运行时 ID。定时与人工 START/RECOVER 命令会携带项目绑定的 Avatar ID，Gateway 在执行前核验当前 LiveTalking 会话实际 `avatar_id`，场次预检也会单独显示项目形象核验结果；不匹配、绑定过期或运行时未报告形象时均阻塞开播。桌面工坊现可为项目创建 WebRTC 预览会话：控制台确认项目输出、当前已发布 Avatar 和场次状态后，由 Runtime Gateway 将项目 Avatar 注入 LiveTalking RTC offer，返回 session 后自动绑定场次；单路容量占用会明确失败。真实浏览器到 LiveTalking 的 ICE/媒体网络可达性、4090 推理负载与运行中受控切换仍待部署验收。Studio 语音预览端点已实现代码级 Gateway 鉴权、开播互斥、活跃场次拒绝和 WAV 响应；仍需部署 CosyVoice/Gateway 并验证真实声线和 GPU 资源表现。服务端录播元数据与不可变内容证据可入库；媒体服务没有部署符合 `MEDIA_UPLOAD_CONTRACT.md` 的读取授权操作前，跨设备下载入口会返回服务错误，不会退回暴露对象存储凭据；录播脚本包仍是独立制作文档。
