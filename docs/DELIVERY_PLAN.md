# 实施计划与交付边界

## P0：单卡技术验证

目标：验证一张 4090 能否稳定驱动授权真人素材并输出测试推流。

交付：

- Linux/Docker/CUDA 环境检查清单与 `scripts/check-runtime-host.sh` 的可执行主机预检。
- PostgreSQL 归档备份、校验与隔离恢复演练；录屏落盘到受控主机路径并站外复制。
- LiveTalking、MuseTalk、CosyVoice 的固定版本清单。
- 以外置补丁导出 LiveTalking 会话、录制、推理/输出 FPS 与 RTMP writer 观测，并在真实平台目的端补充独立回执、实测码率与音画同步探针。
- 每场次以私网 runtime-observer 绑定租户级遥测密钥、真实会话与输出探针；完成探针失效后的 fail-closed 降级演练。
- 授权形象素材的本地预览。
- 测试 RTMP 输出、健康检查和 4 小时连续运行报告。

不在 P0 内：商品问答、平台账号运营、自动下单、全自动直播。

## P1：可开播的混合媒体系统

目标：由场控安全地把预制真人内容和实时数字人组合成一场直播。

交付：

- 场次节目单、SKU 绑定和预制片段管理。
- 实时欢迎语、SKU 切换和白名单 FAQ。
- 字幕、AI 标识、录屏分段、RTMP 重连和一键切真人。
- 场控操作页与事件日志。

## P2：商品事实和风控闭环

目标：实时问题只能在审核过的商业事实范围内回答。

交付：

- SKU、价格、库存、活动、资质和售后数据导入。
- RAG 检索证据、版本管理、禁说规则和转人工队列。
- 对话审计、模型/提示词版本记录、异常告警。
- 真实直播的漏斗与风险报告。

## P3：生产稳定性

目标：在人工值守下连续稳定运营，而不是宣称完全无人直播。

交付：

- 进程守护、故障降级、告警和恢复演练。
- 直播回放、问题复盘、策略灰度和场次数据看板。
- 平台规则、AI 标识、肖像声音授权和商品资料的上线检查单。

## 所需输入

| 输入 | P0 | P1 | P2 |
| --- | --- | --- | --- |
| 可访问的 Linux 4090 | 必须 | 必须 | 必须 |
| 授权人物视频/声音 | 必须 | 必须 | 必须 |
| 测试 RTMP | 必须 | 必须 | 必须 |
| 商品和脚本 | 可选 | 必须 | 必须 |
| 价格库存接口或导出 | 不需要 | 可选 | 必须 |
| 直播场控人员 | 不需要 | 必须 | 必须 |

## 不能承诺的内容

- 规避任何直播平台的审核、AI 标识或账号规则。
- 使用无授权人物肖像、声音或商品素材。
- 把单卡 4090 宣传为多路 1080p、全身、高保真、24 小时无人直播方案。
- 在没有真实商品数据和运营测试的前提下承诺成交或 GMV。
