# 框架状态

当前代码仓库已经具备不依赖 GPU 的产品框架：

> **当前目标与运行边界（2026-11-11）**：桌面版按“一个内容项目、两个输出”收敛——同一项目的审核素材、数字人形象、商品事实、提示词/脚本和发布记录，分别生成录播视频与实时直播。远程 Ubuntu 24.04 + RTX 4090 的 Docker GPU smoke 已通过，容器内 CUDA/`nvidia-smi` 可用；但当前主机约 78 GiB 可用空间，低于生产要求的 150 GiB，因此这只是运行链路 smoke，不是生产放行（[V-20261111-03](VERIFICATION_LOG.md#v-20261111-03)、[V-20261111-07](VERIFICATION_LOG.md#v-20261111-07)；外部证据的治理判定仍为“未验证”）。

> 2026-11-04 状态更正：实时插播/回退已由冻结脚本、Gateway 受绑定回执和数据库游标控制；独立输出验证器可将已送达指令、会话、冻结片段、内容 SHA-256 与证据引用写入 append-only 观测记录。控制面只接受专用服务 token 提交、按租户 Ed25519 公钥验证、且 audience 绑定为 `tenantId:runId` 的短时证明；Gateway 接受回执本身仍不构成实际直播输出已播出的证据，生产需部署实际水印/指纹或目的端回放验证器。

平台结算方面，渠道经营事件仍只用于漏斗和运营估算；独立的私网结算入口会接收带来源 SHA-256 与受控证据引用的账单，数据库冻结批次/行项目，并按订单生成差异，由审核员或管理员带证据结案。它不替代任何具体平台的账单下载、费用口径或真实打款验收。

### 成员授权闭环

`054_governed_membership_authorization.sql` 将 `memberships` 变为带 `active`、`suspended`、`revoked` 状态的受 RLS 保护记录，并为每个成员分配稳定 ID。生产请求仅使用 OIDC 令牌中经签名校验的 `tenant_id` 和 `sub` 识别主体，再查询该租户的有效成员角色；令牌携带的 `role` 不会创建成员、恢复成员或改写数据库角色。所有面向人工的 API 方法在服务端显式执行角色判断，`npm run membership:authz:check` 会防止新路由重新依赖代理层的 JWT 角色。管理员通过控制台 `/memberships` 或 `/api/v1/memberships` 显式创建成员、通过 `/api/v1/memberships/:membershipId` 变更角色或状态；操作会写入租户审计链，管理员不能修改自身成员关系，数据库也会拒绝撤销最后一位有效管理员。

新租户的第一位管理员必须在已受控的部署窗口创建，命令只允许在该租户尚无有效管理员时执行，并同样写入审计链：

```powershell
npm run membership:bootstrap-admin -- --tenant-id <tenant-uuid> --subject <oidc-subject> --display-name <name>
```

### 成员资源范围

`057_membership_resource_scopes.sql` 在既有成员角色上增加 `tenant` 与 `restricted` 两种访问模式。旧成员默认 `tenant`，升级不会导致现有管理员或运营成员失去访问；管理员也不能切换为 `restricted`。受限成员可被分配到具体 `channel_connection` 或 `live_run`：频道范围可访问该频道关联的全部直播，直播范围仅可访问该场次。范围记录通过触发器校验会员、频道或直播必须属于同一租户，并受 RLS 强制隔离。

生产认证会从有效数据库 membership 读取稳定 membership ID 与访问模式，JWT 仍只用于验证身份。控制台 `/memberships` 允许管理员将非管理员成员改为受限并勾选频道/场次，变更会写入审计链。控制面在频道列表/读取/验证、直播列表/读取/生命周期/命令/语音派发/会话绑定，以及节目、节目修订、互动、渠道回复、遥测/SLO、发布清单、运行时间线、经营汇总和按场次策略服务中重新验证范围；没有范围的受限成员默认看不到任何直播或频道。告警、事故单、录制证据和运行时 outbox 的全局列表也会过滤至已分配场次，未授权 ID 不能用于确认告警、创建/关闭事故或读取/人工投递命令。受限成员也不能读取或更改商品、素材、模型发布、策略、额度和全租户审计，不能新建频道或场次；但其被授权场次的时间线仍只能聚合该 `runId` 的审计事实。`npm run membership:scopes:check` 与 `npm run governance:tenant-scope:check` 阻止服务和页面绕过，CI PostgreSQL 集成测试验证 API 列表过滤、未授权直播 404、直播范围不赋予频道管理权限、运行证据列表/操作隔离、全租户治理 API 的 `403`，以及恢复全租户访问，见 [run 42040219509 @ fd9179d](VERIFICATION_LOG.md#v-20261105-20)（`control-plane:integration` 为 success）。

### 渠道人工回复闭环

`053_channel_reply_workflow.sql` 把渠道互动回复建模为受 RLS 和数据库触发器约束的持久化工单：`draft -> pending_approval -> approved -> sending -> sent`，投递失败进入 `failed`，只能回到已批准状态后显式重试。正文 SHA-256、来源渠道、策略结论、证据快照和商品版本在送审后冻结；创建人不能批准自己的草稿，删除和跨渠道改写会被数据库拒绝。只有 runtime-worker 经独立 `CHANNEL_ADAPTER_DISPATCH_TOKEN` 调用私网渠道适配器、适配器收到 provider `providerMessageId` 后，回复才会标记 `sent` 并自动关闭原互动。控制台指挥台提供草稿、送审、审批/拒绝、投递与失败重试，投递队列与场次时间线可显示渠道回复；旧“标记已处理”接口不再能关闭来源于渠道的互动。

仓库提供的是标准化 provider bridge 契约，不是任一平台的 OAuth 实现。每个目标渠道仍需在受控部署中配置 `providerReplyEndpoint`、独立 provider 凭据、平台应用审核和评论回复权限；没有这些外部账号条件，系统会保持未投递或失败，不会伪造“已发送”。

### 值班运行手册

控制台 `/runbooks` 以只读、角色受控方式固化 GPU 显存、模型/TTS 超时、黑屏、RTMP 拒绝、商品事实不同步和违规话术的 P1/P2 处置步骤。每项定义触发条件、责任角色、响应目标、恢复顺序和必须留存的证据；实际操作仍需通过场控、事故单、发布治理和审计链路执行与记录。

### 互动输入边界

策略引擎统一限制互动、草稿和播报前问题为 1 至 1000 字符，并以 Unicode 规范化和空白/零宽字符剥离后识别策略绕过。红队回归覆盖空白混淆提示注入、多轮绕过式追问和超长内容耗尽；未知或超长输入不会进入自动播报。

### 活动音频监测

输出质量探针现在必须返回独立测得的 `audioActive`。缺失、静音或探针不可用都会被 observer 以 fail-closed 遥测写入，控制面生成 `audio_silence` 严重告警、进入降级链路，并从告警直接链接至静音处置手册。此字段需要租机后的独立音频分析器提供真实事实，不能由数字人进程自报。

仓库内 `output-probe` 已实现对受控输出流的 `ffmpeg silencedetect` 活动音频采样；`runtime-observer` 从只读受管目标目录热重载当前场次的会话、租户遥测密钥和输出探针绑定，错误配置会使其健康检查失败而不是要求重启媒体栈。租机后仍需提供合法的中继或回放流，且音画同步继续由独立探针事实证明。

### 默认预设、AIGC 标识与互动规则（P0）

**默认预设库。** `082_runtime_presets.sql` 建立平台级只读目录 `runtime_presets`，种子为默认女声 `preset-zh-female`、默认男声 `preset-zh-male` 和形象槽位 `preset-avatar-default`，商用授权状态都是 `unverified`。资产页“从默认库添加”调用 `/api/v1/presets/{presetCode}/adopt`，把运营方上传的授权素材登记为本租户的待审核资产，仍经内容校验和独立审批；Gateway 以 `COSYVOICE_SFT_SPEAKER_MAP`（空值时用内置映射）把预设声音换成 sft 说话人。仓库不附带素材，许可与肖像、声音授权见 EP-16；sft 默认声音需要自带说话人的 CosyVoice 权重和 4090 主机。

**AIGC 标识。** `livetalking-aigc-label.patch` 与 `runtime/livetalking/shuzhiren_aigc_label.py` 在每一帧推流和录制画面上绘制显式标识（镜像安装 `fonts-noto-cjk`），标识不能关闭，绘制失败时丢帧而不是推出无标识画面。Gateway `/healthz` 透传 `aigc_label`，开播前检查项 `aigc_label` 要求运行时报告的文字与场次 release manifest 封存的文字一致；`083_recording_aigc_label.sql` 与 manifest 的 `aigc` 字段保存隐式标识元数据，`deploy:check` 拒绝关闭或不一致的标识配置。隐式标识尚未写入 RTMP 流或录制文件元数据。4090 与抖音观看端的画面核验见 RW-000-12，法务与平台的合规结论见 EP-15。

**互动规则引擎。** `084_interaction_rules.sql` 建立受审批的 `interaction_rules` 与只追加的 `interaction_rule_firings`。runtime-worker 的独立循环对 `LIVE` 场次评估观众进场、关注、礼物、评论关键词、定时和冷场六类触发，渲染后的话术经策略引擎（与控制台同一份规则的 JS 副本）判定，再写入绑定冻结声线与商品版本的 `speech.dispatch` outbox，或生成仍需人工审批的渠道回复草稿；每次决定在触发记录中只写一行，表的唯一键使多个 worker 同时运行时同一触发只处理一次。控制台提供 `/interaction-rules` 页面、规则审批和场次触发记录，Channel_Adapter 归一化 Webhook 新增 `viewer_event`。接入真实抖音事件需要抖音开放平台权限（EP-17）与仓库中尚未编写的抖音 Webhook Adapter（RW-040-02）。

## 最近治理闭环

### 冻结运行脚本与受控节目切换

`064_governed_runtime_program_scripts.sql` 为节目段落增加 `runtime_script`，并要求预制讲品与受控互动段落在批准或候选修订送审前具有 1 至 800 字符的冻结脚本。脚本被纳入节目哈希、草稿保存、候选修订克隆和运营编辑器；数据库分别在节目批准与候选修订送审时拒绝缺失脚本的可运行段落。历史批准节目保持可读，运营需通过受控候选修订补齐脚本，不能直接改写历史内容。

`065_governed_program_transition_cursor.sql` 进一步为直播场次增加当前节目、插播来源、当前插播和待确认 outbox 游标，并在数据库层验证这些段落属于场次冻结修订、插播游标一致、待确认事件确为该场次的媒体 outbox。`START`、`RECOVER` 和定时开播会优先携带当前或首个冻结可运行段落；仅在受绑定 Gateway 回执后建立主节目游标并写入 `live_program.activation_accepted`，使首次插播也有可恢复来源。缺少冻结首段的定时场次会清除排期、告警并等待人工修复后重新排期。控制台只允许在 `LIVE` 场次插播已批准修订中的冻结脚本；插播和回退在 Gateway 回执前均保持原游标，并拒绝并发或嵌套插播。worker 和人工 outbox 投递会校验 UUID 段落、脚本 SHA-256、回执中的命令/会话/动作/段落和新鲜时间，随后才原子移动游标并写入 `live_program.transition_accepted` 审计事件。Gateway 仅将冻结脚本交给 LiveTalking 并返回 `livetalking_api_accepted` 回执；它证明下游 API 已接受请求，不证明平台目的端、视频画面或音频已经实际播放。

`066_program_output_observations.sql` 为“实际输出已观测”建立 append-only 证据表。它把租户、场次、运行时会话、已送达媒体 outbox、媒体命令、当前冻结修订段落、验证器来源、内容 SHA-256、媒体时间、置信度和 `evidence://`/`urn:` 引用绑定在同一记录中；控制面和数据库都拒绝未送达、会话/命令/段落不匹配、跨租户或重复但内容不同的证明，写入同时进入哈希链审计 `live_program.output_observed`。`output-probe` 仅在私网 `programEvidenceUrl` 返回完整验证器证明时保留该数据，`runtime-observer` 才以租户服务 token 转发；验证器不可用不会从帧率或 Gateway 回执伪造播出证据。场次时间线把该结果标记为“输出已观测”，与仅表示 API 已接受的媒体投递分开。

当前仍不能把该能力作为真实直播质量结论：仓库已提供将外部输出观测与节目段落关联的取证入口，但部署验收必须实际运行同网段水印/指纹或目的端回放验证器，并覆盖 Gateway 重启、回执丢失、多 worker、RTMP 拒绝、黑屏和静音。GPU、平台账号、推流密钥、验证器、平台回放/指标和真实验收证据均是外部前置条件；首个目标平台已定为抖音（D1，2026-11-05）；抖音 Adapter 尚未实现（RW-040-01 至 RW-040-04：代码未完成），需另立规格。

审核员撤销已冻结的模型发布包或授权素材时，生产事务会锁定所有仍处于 `LIVE` 的关联场次，将其原子切换到 `DEGRADED`，为已绑定运行时会话的场次写入 `switch_to_human` outbox 指令，并针对每个受影响场次封存 `live_run.governance_quarantined` 审计事件。撤销 API 与控制台会返回并显示隔离场次数和实际入队的人工接管数；已处于降级状态的场次不会因第二次关联撤销被重复计数或重复入队。撤销请求同样受 16 KiB JSON 请求体上限保护。
